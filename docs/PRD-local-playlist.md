## 0. 项目信息

| 项 | 内容 |
|---|---|
| Language | 简体中文 |
| 端 | Android（Kotlin 原生，`android/`） |
| 仓库 | `yinfu-music` |
| 本项目既定技术栈 | Kotlin 1.9.24 + Media3 ExoPlayer + Material Components + ViewBinding；本地存储统一 `SharedPreferences + org.json`（**不引入 Room、不新增依赖**） |
| 原始需求（用户原话） | 「创建歌单系统，默认歌单"我喜欢的音乐"，在播放按钮点击小红心添加到"我喜欢的音乐"，再次点击从歌单取消。歌单里面要有歌名，歌手，图片，来自哪个音源（包括解析后的音源地址），下次从歌单点进去能直接播放，就不用再解析音源。」 |

### 用户已拍板的范围决策（**不再作为待确认项，不得更改**）

1. **多张自建歌单**：除内置默认歌单「我喜欢的音乐」外，支持新建 / 重命名 / 删除歌单；歌曲可通过「加入歌单」选择器加入任意歌单；**一首歌可同时属于多张歌单**。
2. **直链策略 = 缓存优先 + 失效自动重解析回填**：从歌单点歌时，若条目已缓存播放直链 → 直接播放、**完全不解析**；若播放失败（直链过期等）→ 自动重新解析一次，并用新地址**回填该歌单条目**，用户无感。
3. 默认歌单「我喜欢的音乐」**不可删除、不可重命名**，始终存在。

## 1. 产品目标与一句话定位

**一句话定位**：给「音符」Android 端加一套**纯本地、零登录、可归类、再听秒播**的歌单系统。

**三个正交目标**

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 让听过的歌能沉淀 —— 一键收藏 + 多歌单归类 | 播放页一次点击即可收藏 / 取消；一首歌可归入任意多张歌单 |
| G2 | 让"再听一次"变快 —— 歌单条目携带缓存直链，点开秒播 | 从歌单点击一条**已解析过**的歌，不触发任何音源解析，立即开始播放 |
| G3 | 让直链失效对用户无感 —— 自动重解析并回填 | 直链过期后播放失败时，自动重解析一次并写回歌单条目，随后可正常播放，无需用户手动操作 |

**非目标（本需求不做）**：账号体系、云同步、社交分享、跨端同步、在线歌单（网易云远程歌单是既有独立功能，不在本次范围内）。

## 2. 用户故事

> 所有故事中的"我"均为 Android 端普通用户。

| # | 场景 | 用户故事 |
|---|---|---|
| US1 | 播放页收藏一首歌 | As a 正在听歌的用户，I want 点播放页小红心把当前歌加进「我喜欢的音乐」，so that 我以后能再找到它。 |
| US2 | 取消收藏 | As a 已收藏过某歌的用户，I want 再点一次红心把它从「我喜欢的音乐」移除，so that 歌单里只留我真正喜欢的。 |
| US3 | 从搜索结果 / 首页把歌加进指定歌单 | As a 正在浏览搜索结果的用户，I want 长按某条歌曲选择"加入歌单"并勾选目标歌单，so that 我能把歌归类到自建歌单里。 |
| US4 | 新建歌单 | As a 想整理音乐的用户，I want 新建一张歌单并起名，so that 我能按心情/主题分类。 |
| US5 | 重命名歌单 | As a 建过歌单的用户，I want 改掉自建歌单的名字，so that 名字能一直贴合我的内容。 |
| US6 | 删除歌单 | As a 不再需要某歌单的用户，I want 删除它，so that 列表保持干净（默认歌单不可删）。 |
| US7 | 一首歌加进多张歌单 | As a 用户，I want 把同一首歌同时放进"通勤"和"跑步"两张歌单，so that 我不必为了归类而复制歌曲。 |
| US8 | 从歌单点歌秒播 | As a 用户，I want 在歌单详情点一条**以前播过**的歌就直接播放、不看到"解析中"，so that 再听没有等待。 |
| US9 | 直链失效后自动恢复 | As a 用户，I want 点一条直链已过期的歌时它自己恢复播放，so that 我不用理解"直链过期"这种事。 |
| US10 | 查看条目上的解析地址 | As a 想确认这首歌来源的用户，I want 在歌单条目上看到音源中文名和**解析后的播放地址**，并能长按复制完整地址，so that 我能核对/取用这条链接。 |

```
└── Button/TextView id=btn_cancel 「取消」
```

交互流程（US3 / US7）：

1. 长按搜索页 / 首页某条歌曲 → 弹出操作菜单（含「加入歌单」「下载」等）→ 选「加入歌单」。
2. 打开选择器，**复选框实时勾选**：哪张歌单已包含此歌就打勾。
3. 用户可勾选/取消勾选任意多张歌单 —— **一首歌可同时属于多张**。
4. 点「确定」→ 一次性把"新增"的歌单写入、"取消勾选"的歌单移除 → Toast「已更新」→ 关闭。
5. 点「取消」/点外部 → 不产生任何写入（放弃本次改动）。
6. 中途点「+ 新建歌单」→ 走 S6 创建 → 成功后回到选择器并**自动勾选**新歌单。

### 4.7 ⭐ S4/条目 —— 歌单条目信息设计（重点）

**每个歌单条目必须展示 5 项信息**：封面图、歌名、歌手、音源中文名、**解析后的播放地址**。

建议布局 `item_playlist_song.xml`（在既有 `item_song.xml` 基础上**增加一行地址行**，其余保持视觉一致）：

```
LinearLayout(horizontal)  height≈80dp（比 item_song 的 72dp 略高，容纳地址行）  paddingHorizontal=16dp
├── ImageView  id=cover    48dp  centerCrop  background=@drawable/bg_gradient_accent   ①封面图
├── LinearLayout(vertical)  weight=1  marginStart=12dp
│     ├── LinearLayout(horizontal)
│     │     ├── TextView id=title  歌名  15sp/text  maxLines=1 ellipsize=end  weight=1
│     │     └── TextView id=duration 时长 11sp/text_3
│     ├── LinearLayout(horizontal)  marginTop=2dp
│     │     ├── TextView id=artist  歌手  12sp/text_2  maxLines=1 ellipsize=end  weight=1
│     │     └── TextView id=source  音源中文名  11sp/teal  maxLines=1 ellipsize=end  ②如「咪咕音乐」「网易云音乐」
│     └── TextView id=play_url     ③解析后的播放地址  11sp/text_3
│           maxLines=1  ellipsize=middle（或 end）  marginTop=2dp  单行
└── ImageButton id=btn_item_more   36dp（可选：移除/更多，P1）
```

**③ 解析后的播放地址 —— 窄屏呈现规则（本 PRD 明确裁定）**：

| 情况 | 呈现 |
|---|---|
| 地址**有效**（`playUrl` 以 `http` 开头） | **单行显示，超出用 `ellipsize="middle"` 从中间截断**（保留域名头 + 文件尾，比纯尾部截断更有辨识度），如 `https://…/abc123.mp3` |
| 地址**过长** | 同上，不做多行展开（保持列表行高统一） |
| **长按地址行** | **复制完整地址**到剪贴板（Toast「已复制播放地址」，P1-3）；这是用户获取完整地址的唯一途径，**必须有** |
| 地址**为空 / 尚未解析过** | 显示占位文案 **「未解析 · 播放时自动解析」**，颜色用 `text_3`（弱化），**不得留空、不得显示 null** |
| 复制失败（无剪贴板权限等极端情况） | 静默失败或 Toast 提示，不得崩溃 |

> 说明：地址行**始终占位显示一行**，无论是否有地址，保证列表行高稳定、不会因解析状态变化而跳动。

**音源中文名（②）**：沿用项目既有映射（已适配音源取 `BuiltinSources.BY_ID[id].label`，否则回落硬编码直连表，最后回落源 id），**不新增映射表**。

### 4.8 S6 —— 新建 / 重命名歌单弹窗

使用 `AlertDialog` + 一个 `EditText`（`dialog_playlist_name.xml`）。

```
LinearLayout(vertical)  padding=20dp
└── EditText id=input_name   hint「歌单名称」  maxLength=20  单行
```

**输入校验（P0-7 / P0-8）**：

| 校验 | 规则 | 不通过时 |
|---|---|---|
| 非空 | 去首尾空格后长度 ≥ 1 | 输入框报错 / Toast「歌单名称不能为空」，不关闭弹窗 |
| 长度 | 去首尾空格后 ≤ 20 个字符 | 提示「歌单名称最多 20 个字」 |
| 同名 | 与**现有任意歌单**（忽略大小写与首尾空格）重名 → 拒绝 | Toast「已有同名歌单」，不关闭弹窗 |
| 重命名未改动 | 新名与原名（忽略大小写空格）相同 | 直接关闭，不产生变更（或提示"名称未变化"） |
| 保留名 | 新歌单不得命名为「我喜欢的音乐」 | 视为同名冲突，拒绝 |

按钮：`确定`（校验通过才写入并关闭）/ `取消`。

## 5. 边界与异常

| # | 场景 | 期望行为 |
|---|---|---|
| 5.1 | **默认歌单不可删不可改名** | 列表项不渲染重命名/删除入口；即使通过任何路径发起删除/改名请求，也必须被拒绝（防御性校验） |
| 5.2 | **空歌单** | 详情页显示空态文案（见 4.5）；列表页仍显示「歌单名 · 0 首」 |
| 5.3 | **同名歌单** | 新建/重命名一律拒绝（忽略大小写与首尾空格），提示「已有同名歌单」 |
| 5.4 | **重复收藏同一首** | **幂等**：已在默认歌单再次点击红心 = 移除（红心本身是开关）；「加入歌单」选择器对已包含的歌单显示为已勾选，重复确认不产生重复条目。**任何歌单内同一首歌不得出现两条记录** |
| 5.5 | **直链失效** | 播放失败时自动重解析**一次**并回填该歌单条目（含新地址），随后继续播放；UI 不弹"解析中"以外的阻碍；条目地址行同步刷新为新地址 |
| 5.6 | **重解析仍失败** | 给出明确失败提示（Toast，复用现有 `repo.error` 提示风格），**不自动跳歌**（与项目既有"不会自动跳歌名"原则一致）；条目地址行保持原值或占位，不做错误回填 |
| 5.7 | **无网络** | 播放已缓存直链的歌**仍可播**（缓存优先）；无缓存且无网络 → 播放失败提示，不崩溃 |
| 5.8 | **歌单被删除时该歌正在播放** | 播放**不中断**，歌继续放完；仅从列表移除该歌单。若被删的是当前播放队列的来源歌单，队列按既有行为继续（不强制清空队列） |
| 5.9 | **首次安装 / 无任何歌单数据** | 自动创建默认歌单「我喜欢的音乐」（空）；不报错、不弹窗 |
| 5.10 | **存储损坏** | 读取到非法/损坏 JSON 时降级为"仅默认歌单"的空状态并静默处理，**绝不允许崩溃**，不影响搜索/播放等既有功能 |
| 5.11 | **无播放中歌曲时点红心** | 无效果或提示，不能写入 null 歌曲 |
| 5.12 | **封面缺失 / 加载失败** | 显示既有渐变占位（`bg_gradient_accent`），不出现崩溃或空白异常 |
| 5.13 | **歌名为空 / 歌单名超长** | 歌名空串按占位处理；歌单名长度受 4.8 校验约束 |
| 5.14 | **解析地址为非 http 值** | 视为"未解析"，地址行显示占位文案（与 `hasPlayUrl` 语义一致） |
